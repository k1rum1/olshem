## Проектирование базы данных
1. **Анализ предметной области** — какие объекты и какие вопросы будут к базе. Например, «школа»: ученики, классы, предметы, оценки.
2. **Выделение таблиц и полей** — по одной таблице на тип объектов, у каждого поля свой тип.
3. **Выбор первичных ключей и связей** — между таблицами строят **схему данных**.
4. **Создание** таблиц в СУБД (в Access — в режиме **Конструктор**) или командой SQL.
5. **Ввод данных** — вручную, через **формы** или импортом.
6. **Запросы и отчёты** — получение ответов.

**Объекты СУБД (на примере Access):**

| Объект | Назначение |
|---|---|
| Таблица | хранит данные |
| Форма | удобное окно для ввода и просмотра одной записи; защищает от ошибок ввода |
| Запрос | выбирает, сортирует, считает и изменяет данные по условию |
| Отчёт | оформленный для печати результат: с группировкой, итогами, заголовками |

## SQL
**SQL** (Structured Query Language) — язык структурированных запросов к реляционным базам данных. Его понимают все СУБД. Ключевые слова принято писать заглавными.

**Создание таблицы и данных:**

```sql
CREATE TABLE students (
  id INTEGER PRIMARY KEY,
  name TEXT,
  class TEXT,
  score INTEGER
);
INSERT INTO students (id, name, class, score) VALUES (1, 'Айдана', '10А', 92);
UPDATE students SET score = 95 WHERE id = 1;
DELETE FROM students WHERE score < 20;
```

## Выборка: SELECT
```sql
SELECT name, score          -- какие поля (* — все)
FROM students               -- из какой таблицы
WHERE class = '10А'         -- условие отбора
ORDER BY score DESC;        -- сортировка: ASC по возрастанию, DESC по убыванию
```

**Условия в WHERE:**
- сравнения: `=`, `<>` (не равно), `<`, `>`, `<=`, `>=`;
- логика: `AND`, `OR`, `NOT`;
- `BETWEEN 60 AND 80` — диапазон включительно;
- `IN ('10А', '10Б')` — одно из значений;
- `LIKE 'А%'` — шаблон: `%` — любое количество символов, `_` — ровно один символ;
- `IS NULL` — пустое значение.

**Агрегатные функции** считают по группе строк: `COUNT(*)` — количество, `SUM`, `AVG` — среднее, `MIN`, `MAX`.

```sql
SELECT class, COUNT(*) AS students, AVG(score) AS avg_score
FROM students
GROUP BY class              -- по группе на каждый класс
HAVING AVG(score) > 70      -- условие для групп (WHERE — для строк)
ORDER BY avg_score DESC;
```

Порядок частей запроса строго такой: `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY`.

## Объединение таблиц: JOIN
```sql
SELECT s.name, g.subject, g.score
FROM students AS s
JOIN grades AS g ON g.student_id = s.id
WHERE g.subject = 'Информатика';
```

`JOIN … ON` соединяет строки двух таблиц, у которых совпадает ключ: внешний ключ `grades.student_id` с первичным ключом `students.id`. `INNER JOIN` (просто `JOIN`) оставляет только пары с совпадением. `LEFT JOIN` оставляет все строки левой таблицы, даже если пары нет.

## Пример: аналитика по результатам
Таблица `results(student, topic, textbook, score)` — такая же, как в платформе Өлшем. Средний балл по темам, начиная с самых слабых:

```sql
SELECT topic, ROUND(AVG(score), 1) AS avg_score,
       SUM(CASE WHEN score < 40 THEN 1 ELSE 0 END) AS failed
FROM results
GROUP BY topic
ORDER BY avg_score;
```

## Связь веб-страницы с базой данных
На динамическом сайте страница не хранит данные сама. Браузер отправляет запрос на сервер, серверная программа (на PHP, Python и других языках) выполняет SQL-запрос к базе и собирает из ответа HTML-страницу. Так работают электронный дневник, интернет-магазин, поиск по сайту. Данные пользователь вводит через HTML-форму (`<form>`, `<input>`, `<button>`), а сервер записывает их в базу командой `INSERT`.

> Данные из формы нельзя вставлять в SQL-запрос простой склейкой строк: злоумышленник может ввести кусок SQL-кода (атака **SQL-инъекция**). Используют параметризованные запросы.

- JOIN :: объединение строк двух таблиц по ключу
- SQL-инъекция :: атака через вставку SQL-кода в данные формы
