## Большие данные (Big Data)
**Big Data** — настолько большие, быстро растущие и разнородные данные, что их нельзя обработать обычными программами на одном компьютере. Их источники: датчики и умные устройства, банковские транзакции, социальные сети, камеры, GPS, электронные дневники.

Большие данные описывают признаками «V»:
- **Volume** — огромный объём (терабайты и петабайты);
- **Velocity** — высокая скорость появления и обработки;
- **Variety** — разнообразие: таблицы, тексты, фото, видео;
- **Veracity** — достоверность, данные бывают неточными;
- **Value** — ценность: смысл есть, только если данные помогают принимать решения.

**Где применяют:** прогноз пробок и погоды, рекомендации в магазинах и стримингах, выявление мошенничества в банках, медицина. В образовании — анализ результатов тестирования, чтобы найти сложные темы, как в платформе Өлшем.

## База данных и СУБД
**База данных (БД)** — организованная совокупность данных о какой-то предметной области, хранящаяся по определённым правилам. **СУБД** (система управления базами данных) — программа, которая создаёт БД, хранит данные, ищет и изменяет их. Примеры СУБД: Microsoft Access, LibreOffice Base, MySQL, PostgreSQL, SQLite.

**Модели данных:**
- **иерархическая** — дерево: у каждой записи один «родитель» (папки на диске);
- **сетевая** — у записи может быть несколько связей с другими;
- **реляционная** — данные хранятся в связанных **таблицах**. Сегодня самая распространённая модель.

## Реляционная таблица
| Понятие | Что это | Пример |
|---|---|---|
| Таблица (отношение) | данные об одном типе объектов | «Ученики» |
| Запись (строка, кортеж) | один объект | ученик Айдана Серикова |
| Поле (столбец, атрибут) | одно свойство объектов | «Дата рождения» |
| Тип поля | какие значения допустимы | текст, число, дата, логический, счётчик |

**Ученики**

| id_ученика | Фамилия | Имя | Класс |
|---|---|---|---|
| 1 | Серикова | Айдана | 10А |
| 2 | Ким | Руслан | 10Б |

**Требования к таблице:** у каждого поля своё уникальное имя; в ячейке одно значение; нет двух одинаковых записей; порядок строк и столбцов не важен.

## Ключи и связи
**Первичный ключ** — поле (или несколько полей), значение которого **уникально** для каждой записи и не бывает пустым. Фамилия не подходит — бывают однофамильцы. Номер ИИН или счётчик `id` подходят.

**Внешний ключ** — поле таблицы, которое ссылается на первичный ключ другой таблицы. Так таблицы связываются.

**Оценки**

| id_оценки | id_ученика | Предмет | Балл |
|---|---|---|---|
| 1 | 1 | Информатика | 92 |
| 2 | 1 | Алгебра | 78 |
| 3 | 2 | Информатика | 85 |

Здесь `id_ученика` — внешний ключ на таблицу «Ученики».

**Виды связей:**
- **один к одному (1:1)** — ученик ↔ его личное дело;
- **один ко многим (1:М)** — один ученик → много оценок. Самая частая связь;
- **многие ко многим (М:М)** — ученики ↔ кружки. Её реализуют через третью, промежуточную таблицу «Запись в кружок» с двумя внешними ключами.

**Ссылочная целостность** — СУБД не даёт добавить оценку несуществующему ученику и не даёт удалить ученика, у которого есть оценки (или удаляет их вместе с ним каскадно).

## Нормализация
**Нормализация** — разбиение данных на таблицы так, чтобы убрать дублирование и противоречия. Если хранить адрес школы в каждой строке с оценкой, при смене адреса придётся править сотни строк и легко ошибиться. Правильно хранить школы в отдельной таблице и ссылаться на неё ключом.

- **1НФ:** в каждой ячейке одно значение, нет повторяющихся групп.
- **2НФ:** каждое неключевое поле зависит от всего первичного ключа.
- **3НФ:** неключевые поля не зависят друг от друга (только от ключа).

@terms
- Big Data :: огромные, быстро растущие и разнородные данные, требующие особых средств обработки
- База данных :: организованная совокупность данных о предметной области
- СУБД :: программа для создания базы данных и работы с ней
- Реляционная модель :: модель, в которой данные хранятся в связанных таблицах
- Запись :: строка таблицы, данные об одном объекте
- Поле :: столбец таблицы, одно свойство объектов
- Первичный ключ :: поле с уникальными непустыми значениями, идентифицирующее запись
- Внешний ключ :: поле, ссылающееся на первичный ключ другой таблицы
- Нормализация :: разбиение данных на таблицы для устранения дублирования

- Нормализации и ссылочной целостности нет ни в одном учебнике. Добавлены на понятном школьном примере.
- Пример базы взят из школьной жизни (ученики и оценки), чтобы связать главу с аналитикой результатов.
